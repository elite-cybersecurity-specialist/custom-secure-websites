# Security Policy and Coordinated Disclosure

## Reporting security concerns

If you find a suspected vulnerability in an **ECS-owned** website, software component or demonstrator, contact **Yuhisern@protonmail.com** with subject `ECS SECURITY REPORT — [project]` and include a concise impact description, affected component/version, safe reproduction steps and contact method. Please avoid sending live credentials or customer information in the initial message.

## Authorisation and scope

- This repository contains **public descriptive architecture and reference guidance**, not an open invitation to attack third-party websites or infrastructure depicted in diagrams.
- **No scanning, exploit testing, denial-of-service testing, access to data or social engineering is authorized by the publication of this repository.** Obtain written permission and a defined rules-of-engagement document from the actual asset owner before conducting security tests.
- Vulnerabilities in GitHub, Cloudflare, Tor, hosting providers, or payment services should be submitted to those providers through their own reporting channels.
- Customer deployments and sensitive security evidence are not published here.

## Responsible publication

Report vulnerabilities privately before public disclosure. Do not publish keys, credentials, detailed customer attack paths, sensitive host rules or private forensic records. ECS will evaluate legitimate reports and coordinate the appropriate response according to the affected asset and ownership.
